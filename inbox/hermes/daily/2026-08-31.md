## 3. 值得沉淀

1. GUI Git 客户端中的 shell 后台任务不一定真正脱离父进程；重型索引应采用按需执行，或交给具备延迟、防抖、单实例和低优先级能力的系统后台任务。
2. 跨服务数据库事务无法回滚 Redis 或远程库存操作；库存应使用持久化预占记录、幂等状态机和补偿扫描，而不是依赖异常分支的一次性恢复调用。
3. 支付状态必须同时成为列表、后台任务和审核接口的闸门；只在前端增加 `can_review` 无法防止未支付申请被后台捞取。
4. 申请阶段已经确认的库存事实应持久化并在审核阶段复用，避免实时重判造成合法申请无法建单；但业务状态与幂等校验不能一起删除。
5. 本地 Git 索引规避能快速恢复开发体验，但不是仓库级修复；后续仍应由仓库维护者清理错误 gitlink 或补齐 `.gitmodules`。
