### 2.1 内部 GitLab Python CLI 安装与分发

- 定位 `pip install http://...git@main` 失败的直接原因：缺少 `git+`，导致 pip 把 Git 仓库地址当作普通压缩包 URL，收到 HTML/404 后无法解包。

## 3. 值得沉淀

1. `pip` 安装 Git 仓库时，仓库可见性解决的是认证，`git+` 解决的是协议解析；两者不能互相替代。
2. Python CLI 的验证应同时核对发行包名、导入包名和 console script 名，不能从仓库名推断。
3. 服务启动必须绑定可复现依赖环境；Docker 构建、健康检查和启动预检比“缺一个装一个”稳定。
4. 代理排障应按 DNS → TCP/CONNECT → 认证/白名单 → 目标接口逐层定位，错误发生在哪一层就只修哪一层。
5. 浏览器指纹一致性的可靠实现是复用真实浏览器会话，而不是把少量指纹字段复制给独立 HTTP 客户端。
6. 多用户任务必须隔离输入、日志、结果和浏览器资源；单个 VirtualBrowser Worker 同时只租给一个任务。
