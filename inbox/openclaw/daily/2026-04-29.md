### C5. 可迁移设计模式

1. **Skill-File-Per-Directory 架构**：`skills/<category>/<name>/SKILL.md` + 可选 `scripts/` 子目录。每个 skill 自包含，可单独引用。
2. **HITL 诊断循环**（diagnose skill）：`reproduce → minimise → hypothesise → instrument → fix → regression-test`，对应我们的 skill/agent 调试流程。
3. **Grizzling Session**（grill-with-docs）：用 AI 挑战 plan 合理性，同步 CONTEXT.md + ADRs，防止agent 自己觉得自己对。
4. **Caveman 极度压缩通信**：`/caveman` 提供 ~75% token 节省的极简模式。
5. **per-repo setup skill**：引导配置 issue tracker/labels/doc layout，保证其他 skill 使用一致性配置。

### C6. 风险边界

- skill 强耦合 Claude Code/Codex 上下文，部分 script 使用 `#!/bin/bash`，Windows 兼容性有限
- `diagnose` 依赖真实 fs 环境，sandboxed 环境可能受限
- `caveman` 压缩模式会改变输出风格，需使用者明确预期
- 部分 skill 已标记 `deprecated/`（旧版 design-an-interface、qa），迁移注意版本
