### 1. antirez/ds4 (DwarfStar)

- **一句话判断**: Redis 作者 antirez 用 27K 行纯 C 打造的 DeepSeek V4 专用本地推理引擎，"一个模型一个引擎"的极致哲学，是理解现代 LLM 推理底层实现的绝佳教材。
- **Stars**: 15,185 | **License**: MIT | **Language**: C
- **解决的问题**: 传统方案（llama.cpp、vLLM）追求通用性，支持多模型多格式，导致代码复杂度高、针对特定模型的优化空间有限。ds4 反其道行之——只为 DeepSeek V4 Flash/PRO 服务，实现极致的推理性能和 2-bit 量化质量。它替代了"通用 GGUF runner + 模型适配层"的旧方案，直接将模型架构硬编码到引擎中。
- **架构/实现**: 
  - **核心引擎** (`ds4.c`, 27,791 行)：包含 GGUF 加载、tensor 布局、CPU 参考 kernel、Metal/CUDA 图驱动、tokenizer
  - **GPU 后端**：Metal (macOS 主力)、CUDA (NVIDIA DGX Spark / 通用 GPU)、ROCm (AMD Strix Halo)
  - **SSD 流式推理**：当模型超过 RAM 时，非路由权重常驻内存，路由 MoE expert 按需从 SSD 加载
  - **分布式推理**：通过 TCP 将 transformer 层拆分到多台机器，支持流水线 prefill
  - **内置 Agent** (`ds4-agent`)：集成编程代理，可直接对接 coding agent 工作流
  - **关键依赖**：无外部依赖（不链接 GGML），仅用系统库 (mmap, pthread, Metal/CUDA)

- **repo tree 摘要**:

  int ds4_sample_logits(const float *logits, int n_vocab, float temperature,
                        int top_k, float top_p, float min_p, uint64_t *rng) {
      if (!logits || n_vocab <= 0) return 0;
      return sample_top_p_min_p(logits, (uint32_t)n_vocab, temperature, 
                                 top_k, top_p, min_p, rng);
  }

  int ds4_session_top_logprobs(ds4_session *s, ds4_token_score *out, int k) {
      if (!s || !out || k <= 0) return 0;
      if (k > (int)DS4_N_VOCAB) k = (int)DS4_N_VOCAB;
      for (int i = 0; i < k; i++) {
          out[i].id = -1;
          out[i].logit = DS4_NEG_INF;
          out[i].logprob = DS4_NEG_INF;
      }
      float max_logit = DS4_NEG_INF;
      for (uint32_t i = 0; i < DS4_N_VOCAB; i++) {
          const float v = s->logits[i];
          if (!isfinite(v)) continue;
          if (v > max_logit) max_logit = v;
          for (int j = 0; j < k; j++) {
              if (out[j].id < 0 || v > out[j].logit) {
                  for (int l = k - 1; l > j; l--) out[l] = out[l - 1];
                  out[j].id = (int)i;
                  out[j].logit = v;
                  break;
              }
          }
      }
      // 计算 log probabilities
      double sum = 0.0;
      for (uint32_t i = 0; i < DS4_N_VOCAB; i++) {
          const float v = s->logits[i];
          if (isfinite(v)) sum += exp((double)v - (double)max_logit);
      }
      const double logsum = (double)max_logit + log(sum);
      for (int i = 0; i < k && out[i].id >= 0; i++) {
          out[i].logprob = isfinite(out[i].logit) 
              ? (float)((double)out[i].logit - logsum) : DS4_NEG_INF;
      }
      return k;
  }
  ```

  static uint32_t ds4_prefill_cap_for_prompt(int prompt_len,
                                             uint32_t requested_chunk) {
      if (prompt_len <= 0) return 1;
      uint32_t cap = (uint32_t)prompt_len;

      if (requested_chunk != 0) {
          cap = requested_chunk;
      } else {
          const char *env = getenv("DS4_METAL_PREFILL_CHUNK");
          if (env && env[0]) {
              char *endp = NULL;
              const long v = strtol(env, &endp, 10);
              if (endp != env) {
                  if (v <= 0) return cap;
                  cap = (uint32_t)v;
              }
          } else if (prompt_len > 4096) {
              // PRO 模型用更大 chunk，Flash 用 4096
              cap = DS4_MODEL_VARIANT == DS4_VARIANT_PRO ? 8192u : 4096u;
          }
      }
      if (cap == 0) cap = 1;
      if (cap > (uint32_t)prompt_len) cap = (uint32_t)prompt_len;
      return cap;
  }

### 2. baidu/Unlimited-OCR

- **一句话判断**: 百度推出的 One-shot 长文档 OCR 解析系统，支持单次推理处理整页/多页/完整 PDF，以 SGLang 高性能推理引擎为后端，是文档理解领域的重要突破。
- **Stars**: 3,431 | **License**: MIT | **Language**: Python
- **解决的问题**: 传统 OCR 管线（检测→识别→后处理）需要多阶段串联，长文档需要切片后逐段处理再拼接，容易丢失跨页上下文。Unlimited-OCR 用一个端到端模型实现"一次看完整个文档"的解析，替代了 PaddleOCR/DeepSeek-OCR 的多阶段方案。
- **架构/实现**:
  - **模型层**: 基于 HuggingFace Transformers 的视觉语言模型，支持两种推理模式（gundam/base）
  - **推理引擎**: SGLang 高性能推理后端，支持流式输出和自定义 logit processor
  - **防重复机制**: `DeepseekOCRNoRepeatNGramLogitProcessor` — 35-gram 窗口防重复生成
  - **并发推理**: `infer.py` 支持多线程并发请求，自动管理 SGLang 服务器生命周期
  - **PDF 处理**: PyMuPDF 将 PDF 转为 300dpi 图片后逐页送入模型

  def collect_stream_silent(resp, output_file: str | None) -> dict:
      chunks = []
      token_count = 0
      first_token_time = None
      f = open(output_file, "w", encoding="utf-8") if output_file else None
      try:
          for raw_line in resp.iter_lines():
              if not raw_line:
                  continue
              line = raw_line.decode("utf-8") if isinstance(raw_line, bytes) else raw_line
              if not line.startswith("data:"):
                  continue
              data = line[len("data:"):].strip()
              if data == "[DONE]":
                  break
              chunk = json.loads(data)
              delta = chunk["choices"][0]["delta"].get("content", "")
              if not delta:
                  continue
              if first_token_time is None:
                  first_token_time = time.time()
              token_count += 1
              chunks.append(delta)
              if f:
                  f.write(delta)
      finally:
          if f:
              f.close()
      end_time = time.time()
      decode_time = (end_time - first_token_time) if first_token_time and token_count > 1 else 0
      return {"tokens": token_count, "decode_time": decode_time, "text": "".join(chunks)}
  ```

### 3. XiaomiMiMo/MiMo-Code

## 经验沉淀

1. **当构建 AI 推理系统时，应优先考虑"专用引擎"而非"通用框架"** — antirez 的 ds4 证明了，当目标模型确定时，去掉通用性可以大幅降低代码复杂度（27K 行 C vs llama.cpp 的数十万行），同时获得更好的性能和更可控的质量。

2. **当 Agent 需要跨会话工作时，应优先设计分层持久记忆系统** — MiMo-Code 的 MEMORY.md（项目知识）+ checkpoint.md（会话状态）+ notes.md（临时笔记）+ tasks/（任务进度）四层记忆架构，解决了"每次重新理解项目"的 token 浪费问题。

3. **当处理长文档 OCR 时，应优先使用端到端 VLM 而非传统多阶段管线** — Unlimited-OCR 的 One-shot 方案避免了检测→识别→后处理的级联误差，尤其在跨页表格、复杂排版场景下优势明显。

4. **当需要控制 LLM 输出质量时，应优先使用自定义 logit processor 而非后处理** — Unlimited-OCR 的 DeepseekOCRNoRepeatNGramLogitProcessor 在 token 生成阶段就防止重复，比生成后去重更高效且不会破坏文档结构。

5. **当 AI Agent 需要长时间自主工作时，应优先实现"独立评判"机制** — MiMo-Code 的 `/goal` 命令用独立模型评判 Agent 是否真正完成任务，防止 Agent 的"乐观停止"倾向。
