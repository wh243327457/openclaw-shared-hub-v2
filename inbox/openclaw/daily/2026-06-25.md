### 1. raiyanyahya/recall — Claude Code 本地会话记忆

**一句话判断**：解决 Claude Code 每次冷启动需要重新解释项目的痛点，用纯本地算法（零 API 调用）生成会话摘要，是 agent 持久记忆的轻量范本。

**解决的问题**：Claude Code 每次新会话都从零开始，用户需要反复解释项目上下文。现有方案要么手动维护 CLAUDE.md（费力），要么用 `--resume` 重放整个对话（费 token），要么用远程 LLM 总结（费钱 + 隐私风险）。Recall 用本地 TF-IDF+TextRank 填补了"自动、确定性、零成本"的会话记忆空白。

**架构/实现**：
- **Hook 驱动**：通过 Claude Code 的 plugin hooks（SessionStart / Stop / SessionEnd）自动捕获和恢复
- **双文件模型**：`history.md`（追加式日志）+ `context.md`（覆盖式摘要）
- **本地摘要器**：TF-IDF 句向量 → 余弦相似度图 → TextRank（PageRank 迭代）→ top-k 句子
- **双后端**：numpy 加速路径 + 纯 Python 路径，结果完全一致（确定性保证）

```python
def _textrank_python(tokens, idf):
    vecs = _tfidf_sparse(tokens, idf)
    n = len(vecs)
    sim = [[0.0] * n for _ in range(n)]
    for i in range(n):
        for j in range(i + 1, n):
            c = _cosine(vecs[i], vecs[j])
            if c:
                sim[i][j] = sim[j][i] = c
    row_sum = [sum(row) for row in sim]

    scores = [1.0 / n] * n
    base = (1.0 - _DAMPING) / n
    for _ in range(_MAX_ITERS):
        new = [base] * n
        for i in range(n):
            if row_sum[i] == 0.0:
                continue
            share = _DAMPING * scores[i] / row_sum[i]
            row = sim[i]
            for j in range(n):
                w = row[j]
                if w:
                    new[j] += share * w
        if sum(abs(new[i] - scores[i]) for i in range(n)) < _TOL:
            scores = new
            break
        scores = new
    return scores
```

numpy 加速版本 — 矩阵化 TextRank：
```python
def _textrank_numpy(tokens, idf):
    import numpy as np
    vocab = sorted(idf)
    index = {w: i for i, w in enumerate(vocab)}
    n, vsize = len(tokens), len(vocab)
    mat = np.zeros((n, vsize), dtype=np.float64)
    for i, toks in enumerate(tokens):
        if not toks: continue
        length = len(toks)
        for w, c in Counter(toks).items():
            mat[i, index[w]] = (c / length) * idf[w]
    norms = np.sqrt((mat * mat).sum(axis=1, keepdims=True))
    norms[norms == 0] = 1.0
    mat /= norms
    sim = mat @ mat.T
    np.fill_diagonal(sim, 0.0)
    row_sum = sim.sum(axis=1, keepdims=True)
    row_sum[row_sum == 0] = 1.0
    transition = sim / row_sum
    base = (1.0 - _DAMPING) / n
    scores = np.full(n, 1.0 / n)
    for _ in range(_MAX_ITERS):
        prev = scores
        scores = base + _DAMPING * (transition.T @ scores)
        if np.abs(scores - prev).sum() < _TOL: break
    return scores.tolist()
```

确定性选择保证 — numpy 和纯 Python 产出相同结果：
```python
def _select(sentences, scores, k):
    """Top-k sentences by score, returned in original order. Scores are rounded
    before ranking and ties are broken by position, so the sub-epsilon numerical
    difference between the numpy and pure-Python cores can never change which
    sentences are chosen."""
    order = sorted(range(len(sentences)),
                   key=lambda i: (round(scores[i], 10), -i), reverse=True)
    return [sentences[i] for i in sorted(order[:k])]
```

### 2. sums001/Windows-Copilot-API — 免费 Copilot 逆向 API

**一句话判断**：将微软 Copilot 的免费聊天逆向为 OpenAI 兼容 API，零成本获得 GPT-4 级别能力，但依赖 web 会话和 Cloudflare 通行证，适合个人轻量使用。

**解决的问题**：OpenAI API 按量计费，个人开发者和学生难以承受。Windows-Copilot-API 通过逆向 Copilot 的 WebSocket 协议，将免费的消费级 Copilot 变成本地 OpenAI 兼容端点，实现"一个 Microsoft 账号 = 免费 GPT-4 API"。

- **服务层**：FastAPI 实现 OpenAI 兼容 `/v1/chat/completions` 端点
- **限流层**：token bucket 算法，可配置 RPM 和 burst

WebSocket 帧接收 — 自定义 deadline 控制：
```python
@staticmethod
def _recv_frame(wss, deadline: float):
    """Block for one complete WS frame, or return None past deadline."""
    sock_fd = wss.curl.getinfo(CurlInfo.ACTIVESOCKET)
    if sock_fd == _CURL_SOCKET_BAD:
        raise ConnectionError("WebSocket has no active socket")
    chunks = []
    while True:
        try:
            chunk, frame = wss.recv_fragment()
            chunks.append(chunk)
            if frame.bytesleft == 0 and frame.flags & CurlWsFlag.CONT == 0:
                return b"".join(chunks)
        except CurlError as e:
            if e.code != CurlECode.AGAIN:
                raise
            remaining = deadline - time.time()
            if remaining <= 0:
                return None
            select([sock_fd], [], [], min(0.5, remaining))
```

1. **当需要统一多 agent 运行时时，应优先构建 provider harness 归一化层**，因为每个 agent CLI 有自己的事件格式、会话模型和诊断输出，归一化后上层业务逻辑无需适配每个 provider。
2. **当构建 agent 组织平台时，应优先设计"数字员工"抽象（角色、权限、审批）**，因为 agent 不只是工具，而是需要可审计、可授权、可转移的组织资源。
3. **当需要远程执行 agent 任务时，应优先采用独立 daemon 进程 + token 认证**，因为 daemon 可独立部署、独立升级、独立监控，比嵌入式执行更灵活。

## 经验沉淀

1. **当需要 agent 会话持久化时，应优先采用"追加式日志 + 覆盖式摘要"双文件模型**（来自 Recall），因为日志保证完整性、摘要控制 token 成本，两者互补且可独立优化。

2. **当逆向 WebSocket 协议时，应优先识别握手顺序和挑战类型再实现**（来自 Windows-Copilot-API），因为协议对帧顺序有严格要求（setOptions→consents→send），且 PoW 挑战和 Turnstile 的解决方式完全不同。

3. **当构建多 agent 运行时归一化层时，应优先抽象"执行路径 + 事件归一 + 会话传播 + 诊断输出"四个维度**（来自 AgentSpace），因为不同 provider 的差异集中在这四点，归一化后上层业务才能真正 provider-agnostic。

4. **当算法需要可选加速时，应优先实现"纯 stdlib 基线 + 可选依赖"双后端并用确定性测试保证等价**（来自 Recall），因为零依赖安装体验和可复现性远优于强制 pip install。
