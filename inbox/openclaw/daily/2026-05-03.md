## C. 深读项目：ruvnet/ruflo

**选为深读原因：** 今日 trending 第2名（1,299 stars today），Multi-Agent 编排平台，与 Agent 运行时能力直接相关，设计模式最具迁移价值。

### C1. README 核心命令

```bash
# Claude Code 插件安装（推荐）
/plugin marketplace add ruvnet/ruflo
/plugin install ruflo-core@ruflo
/plugin install ruflo-swarm@ruflo
/plugin install ruflo-autopilot@ruflo
/plugin install ruflo-federation@ruflo

# CLI 安装
curl -fsSL https://cdn.jsdelivr.net/gh/ruvnet/ruflo@main/scripts/install.sh | bash
npx ruflo@latest init --wizard
npm install -g ruflo@latest

# MCP Server
claude mcp add ruflo -- npx -y @claude-flow/cli@latest
```

### C5. 可迁移设计模式

| 模式 | 描述 | 可迁移度 |
|------|------|---------|
| **Skill 文件驱动架构** | 每个 Agent 用 `SKILL.md` 定义行为、触发条件、工具集 | 高 — OpenClaw 已有 Skill 机制，可对齐 |
| **`.agents/config.toml` 集中配置** | 结构化配置管理 Agent 路由、记忆、工具 | 高 — 迁移到 OpenClaw config |
| **插件化市场（32插件）** | `plugin marketplace add` + `plugin install` 的发现/安装机制 | 高 — OpenClaw skill 生态可对标 |
| **MCP Server 接入** | 通过 MCP 协议暴露 Agent 能力给 Claude Code | 高 — OpenClaw 已有 MCP 支持 |
| **多 Provider LLM 路由** | 同时支持 Claude/GPT/Gemini/Ollama，自适应路由 | 中 — 需要多模型后端 |
| **Federation 跨机器通信** | Zero-trust 跨 Agent 安全通信 | 中 — 需要安全通道 |
| **自学习记忆（SONA/ReasoningBank）** | Agent 从历史任务中学习优化 | 低 — 需要嵌入向量库 |

## D. Skill 升格判断

**结论：暂不沉淀 / 需要二次验证**

### 理由

1. **Skill 格式可迁移但需二次验证：** `.agents/skills/*/SKILL.md` 与 OpenClaw Skill 格式相似（都是 Markdown 元数据驱动），但 Ruflo 的 Skill 依赖其专有的 Router/MCP 基础设施，OpenClaw 能否直接复用需要验证。
2. **核心价值在架构思路：** 最值得借鉴的是 `.agents/config.toml` + `SKILL.md` 双层 Agent 定义机制，以及插件 marketplace 的发现/安装 UX。这部分可沉淀为 OpenClaw 的设计参考。
3. **待验证项：** 
   - OpenClaw Skill 系统能否读取ruflo风格的 SKILL.md
   - `ruflo-core` 插件的基础设施是否与 OpenClaw 冲突
   - `plugin install` 机制是否能对标 OpenClaw skill 安装

### 建议

- **下一步：** 单独 clone ruflo，测试 `.agents/skills/` 在 OpenClaw 环境下的兼容性，再决定是否升格为正式 Skill。
- **可参考：** `skills/skill-creator/SKILL.md` 用于构建新的 Skill 模板。
