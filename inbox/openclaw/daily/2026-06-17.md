## 深读项目

### 1. DietrichGebert/ponytail — AI Agent 的"懒惰资深工程师"模式

**一句话判断**：这是今年最有价值的 Agent skill 之一——不是教你 Agent 做什么，而是教它 *不做什么*。80-94% 的代码减少不是优化，是范式转变。

**解决的问题**：AI Agent（Claude Code、Codex、Gemini CLI 等）倾向于过度工程化——一个日期选择器会安装 flatpickr、写 wrapper 组件、添加样式表、讨论时区。Ponytail 在每轮 prompt 注入 YAGNI 规则，让 Agent 在写第一行代码前先问自己 6 个问题。

**架构/实现**：
- 核心机制是 **SessionStart lifecycle hook**（Node.js），每次 session 启动时注入规则文本
- 规则按强度分级：`lite`（只问 YAGNI）/ `full`（加 stdlib 优先）/ `ultra`（代码审查模式）
- 支持 13+ Agent 平台：Claude Code、Codex、Copilot CLI、OpenClaw、Gemini CLI、OpenCode、Pi 等
- 每个 Agent 平台有自己的适配层（`.claude-plugin/`、`.codex-plugin/`、`.openclaw/skills/` 等）

**repo tree 摘要**：
```
.agents/plugins/         → Agent marketplace 配置
.claude-plugin/          → Claude Code plugin 定义（plugin.json + marketplace.json）
.codex-plugin/           → Codex plugin 定义
.openclaw/skills/        → OpenClaw skill 包（ponytail/ponytail-review/ponytail-audit/ponytail-debt/ponytail-help）
hooks/                   → Node.js lifecycle hooks（激活、运行时、配置）
skills/                  → 源 skill 模板
scripts/                 → 构建脚本（check-rule-copies.js、build-openclaw-skills.js）
benchmarks/              → promptfoo 基准测试（baseline vs caveman vs ponytail）
commands/                → CLI 命令定义
examples/                → Before/After 代码对比
docs/                    → Agent portability 文档
```

3. **当评估 Agent 输出质量时，应优先用量化基准（代码行数/延迟/成本）而不是主观判断。** Ponytail 用 promptfoo 做 10 次中位数对比，数据说话。

**可尝试实验**：

- 不适用场景: 需要完整工程化的生产代码（如数据库 schema、API 接口设计）

### 2. omnigent-ai/omnigent — 多 Agent 统一管理层

**一句话判断**：这是 Agent 领域的"Docker Compose"——把 Claude Code、Codex、Pi、自定义 Agent 统一到一个 session 中，支持策略管控、云端沙箱、跨设备协作。

**解决的问题**：当前 Agent 生态碎片化严重——每个 Agent 有自己的 session、自己的文件系统、自己的工具权限。想让 Claude Code 写代码 + Codex 做 review + Pi 做测试？需要手动协调三个独立终端。Omnigent 提供统一 session 层，让多 Agent 在同一上下文中协作。

**架构/实现**：
- **CLI 层**（`omnigent/cli.py`）：Click 框架，`omnigent` / `omni` 双入口
- **Chat 层**（`omnigent/chat.py`）：连接 Omnigent 服务器，管理 session 生命周期
- **Harness 抽象层**：`harness_aliases.py` 统一 Claude Code/Codex/Pi/自定义 Agent 的接口
- **Policy 引擎**（`native_policy_hook.py`）：PreToolUse/PostToolUse/UserPromptSubmit 三阶段策略检查
- **Session 生命周期**（`session_lifecycle.py`）：标记 session 开闭状态、title 管理
- **Web UI**（`ap-web/`）：React + Electron 桌面应用
- **服务器**（`host/`）：本地 Uvicorn 服务器，提供 REST API + MCP 端点

**repo tree 摘要**：

### 3. tamnd/kage — 网站离线镜像：浏览器驱动 + 去 JS 化

**一句话判断**：这是"Save As"的终极进化——用真实浏览器渲染页面，然后把所有 JavaScript 扔掉，留下纯粹的 HTML/CSS/图片。打包成单文件后可以传给任何人。

**解决的问题**：浏览器的"另存为"保存的是原始 HTML，依赖 JS 渲染的内容看不到，还保留了追踪脚本。6 个月后打开可能是一个空白页面或永不停止的加载器。Kage 用 headless Chrome 渲染完整 DOM，再剥离所有脚本，留下人类实际看到的内容。

**架构/实现**：
- **clone 命令**：breadth-first 爬虫，尊重 robots.txt，基于内容 SHA-256 去重
- **browser 层**：`go-rod/rod` 驱动 Chrome DevTools Protocol，stealth 模式防检测
- **asset 层**：解析 HTML DOM，下载 CSS/图片/字体到本地，重写引用路径
- **sanitize 层**：删除所有 `<script>` 标签和内联事件处理
- **pack 命令**：打包成 ZIM 档案（兼容 Kiwix 生态）或自包含可执行文件
- **viewer 层**：原生窗口模式（webview_go），可打包成 .app/.AppImage

**repo tree 摘要**：
```
cmd/kage/                → CLI 入口（main.go）
cli/                     → Cobra 命令定义（clone/serve/pack/open）
clone/                   → 核心克隆引擎（cloner/frontier/config/sitemap/stats）
browser/                 → Chrome 池管理（go-rod 驱动）
asset/                   → 资源下载 + HTML 重写（css/html/download）
sanitize/                → JavaScript 剥离
robots/                  → robots.txt 解析器
pack/                    → ZIM/binary/app 打包（appbundle/appdir）

```

// 遍历 DOM 树，找到所有需要下载的资源引用
// <link rel="stylesheet|icon|preload|prefetch"> → 下载并重写 href
// <img src>、<video poster>、<source src> → 下载并重写
// <script> → 删除（sanitize 层处理）
func RewriteHTML(root *html.Node, base *url.URL, sink RefSink) {
    var walk func(n *html.Node)
    walk = func(n *html.Node) {
        if n.Type == html.ElementNode {
            rewriteElement(n, base, sink)
        }
        for c := n.FirstChild; c != nil; c = c.NextSibling {
            walk(c)
        }
    }
    walk(root)
}

## 经验沉淀

1. **当设计 Agent 行为约束时，应优先用"递进式否决"而非"一次性规则列表"。** Ponytail 的 6 级递进决策树比一堆规则更有效——Agent 在每一级都有"停下来"的机会，而不是被一堆规则淹没后选择性忽略。适用于 Hermes skill 设计：将复杂的质量标准转化为递进检查点。

2. **当需要跨 Agent 平台统一管理时，应优先用"策略 hook + 统一 session"架构。** Omnigent 的三层策略拦截（PreToolUse → PostToolUse → UserPromptSubmit）+ 统一 session 模式是目前最成熟的多 Agent 协作方案。适用于 Hermes delegate_task 的策略层扩展。

3. **当需要持久化 Web 内容时，应优先用"渲染 → DOM 提取 → 去脚本 → 本地化资源"四步流程。** Kage 的流程比 wget/curl 高级得多——它保存的是用户实际看到的内容，而不是服务器返回的原始 HTML。适用于 Hermes 的知识库离线归档。
