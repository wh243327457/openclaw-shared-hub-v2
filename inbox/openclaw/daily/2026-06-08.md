#### 依赖分析
- **核心依赖**: Node 18+ + 6 个 MCP server（4 个 npm 固定版本 + 1 个 HTTP + 1 个 Playwright 扩展）
- **供应链风险**:

#### 可复用经验
1. **当需要为多 AI Coding Agent 共享同一份工程规范时，应优先构建"声明式 manifest + 目标适配层"架构（如 `agent.yaml` + `.claude-plugin/`/`.cursor/` 多目录），因为单 Agent 配置无法跨 runtime 复用。**
2. **当 AI agent 在长任务中容易"跑飞"时，应优先把质量门（format/lint/type-check）做成 PostToolUse hook 自动执行（exit code 0 警告，exit code 2 阻塞），因为 prompt 里的"记得跑测试"几乎一定被遗忘。**
3. **当需要给 agent harness 本身做可观测性时，应优先分离"运行记录"和"健康度计算"（如 `skills-health.js` 把 JSONL 文件作为 `--runs-file` 注入），让 health 评估可重放、可单元测试。**

**项目卡片**: `/home/node/.openclaw/shared/runtime/openclaw/github-learning/projects/karpathy-autoresearch.md`（已生成）

#### 一句话判断
**Agent-as-researcher 范式样板**：把"模型训练"重新定义为"agent 在固定时间预算内反复 edit→train→eval→commit 的循环"，是 2026 年"AI 自主科研"实验的最小可运行模板。

#### 解决的问题
传统 ML 研究 = 人类研究员手动改 train.py、跑实验、看 loss、决定是否保留。autoresearch 把整个循环交给 LLM agent 跑，研究员去睡觉。

#### 架构/实现
- **极简 4 文件**: `prepare.py`（只读：数据/eval/常量）+ `train.py`（agent 唯一可改）+ `program.md`（agent 指令）+ `pyproject.toml`（依赖）
- **数据流**: 读 program.md → git checkout 新 branch → 改 train.py → commit → `uv run train.py > run.log 2>&1`（5 分钟）→ grep val_bpb → 写 results.tsv → keep 或 git reset → 循环
- **关键依赖**: `torch==2.9.1` (CUDA 12.8) + `kernels>=0.11.7`（动态下载 FA3）+ `rustbpe>=0.1.0` + `tiktoken>=0.11.0` + `pyarrow>=21.0.0`

train.py         # 26KB - 完整 GPT 模型 + Muon+AdamW 优化器 + 训练循环 (agent 唯一可改)

#### 关键源码文件
- **`program.md`**: agent 的系统提示（Setup / Experimentation / Output format / Logging / Experiment loop 5 节）；含 "NEVER STOP" 原则和 "Simplicity criterion" 显式 reward
- **`train.py`**: 26KB 完整 nanochat 简化版；`GPTConfig` `@dataclass` 7 个超参；`build_model_config(depth)` 是 agent 改架构的主入口；`MuonAdamW` 双优化器

#### ⭐ 源码精读（3 个代码块）

**代码块 1: `train.py:469-481` - 架构生成函数（agent 改架构的主入口）**
```python
def build_model_config(depth):
    base_dim = depth * ASPECT_RATIO
    model_dim = ((base_dim + HEAD_DIM - 1) // HEAD_DIM) * HEAD_DIM
    num_heads = model_dim // HEAD_DIM
    return GPTConfig(
        sequence_len=MAX_SEQ_LEN, vocab_size=vocab_size,
        n_layer=depth, n_head=num_heads, n_kv_head=num_heads, n_embd=model_dim,
        window_pattern=WINDOW_PATTERN,
    )
```
**逻辑摘要**: `n_kv_head == n_head`（无 GQA），`model_dim` 是 `HEAD_DIM` 整数倍。**搜索空间的最顶层抽象**：agent 改 `depth`/`ASPECT_RATIO`/`HEAD_DIM`/`WINDOW_PATTERN` 4 个常量就能改变整个架构。

**代码块 2: `train.py:540-580` - 训练主循环（5 分钟 wall clock 预算）**
```python
while True:
    torch.cuda.synchronize(); t0 = time.time()
    for micro_step in range(grad_accum_steps):
        with autocast_ctx:
            loss = model(x, y)
        train_loss = loss.detach()
        loss = loss / grad_accum_steps
        loss.backward()
        x, y, epoch = next(train_loader)
    progress = min(total_training_time / TIME_BUDGET, 1.0)
    lrm = get_lr_multiplier(progress)
    muon_momentum = get_muon_momentum(step)
    muon_weight_decay = get_weight_decay(progress)
    for group in optimizer.param_groups:
        group["lr"] = group["initial_lr"] * lrm
        if group['kind'] == 'muon':
            group["momentum"] = muon_momentum
            group["weight_decay"] = muon_weight_decay
    optimizer.step(); model.zero_grad(set_to_none=True)
    # Fast fail: abort if loss is exploding or NaN
    if math.isnan(train_loss_f) or train_loss_f > 100:
        print("FAIL"); exit(1)
```
**逻辑摘要**:
- `progress = total_training_time / TIME_BUDGET` 是**所有 schedule 的统一抽象**（LR / momentum / weight decay）
- `train_loss_f > 100` → `exit(1)`（**快速失败**，不让 agent 在发散 run 上花完 5 分钟）
- `gc.collect(); gc.freeze(); gc.disable()` 在 `step == 0`（注释：Python GC 引起 ~500ms stalls）

**代码块 3: `train.py:236-265` - setup_optimizer（按参数 kind 分组）**
```python
def setup_optimizer(self, unembedding_lr=0.004, embedding_lr=0.2, matrix_lr=0.02,
                    adam_betas=(0.8, 0.95), scalar_lr=0.5, weight_decay=0.2):
    # ... matrix params get Muon, others get AdamW
    dmodel_lr_scale = 0.5 ** math.log2(max(1, model_dim / 768))
    print(f"Scaling AdamW LRs by 1/sqrt({model_dim}/768) = {dmodel_lr_scale:.6f}")

```
**逻辑摘要**:
- 4 种参数 4 种 LR（unembedding=0.004, embedding=0.2, matrix=0.02, scalar=0.5）—— nanochat 风格精细调参
- `dmodel_lr_scale = 0.5 ** math.log2(max(1, model_dim / 768))` —— **按 model_dim 缩放 LR**（μP 简化版）
- `adam_betas=(0.8, 0.95)` —— `beta1=0.8` 激进（默认 0.9），表明作者信任短时 momentum

#### 依赖分析
- **核心依赖**: 9 个（torch, kernels, matplotlib, numpy, pandas, pyarrow, requests, rustbpe, tiktoken）
- **供应链风险**:
  - 🟡 **中**: `kernels>=0.11.7`（>= 而非 ==，每次 install 可能不同）
  - 🟠 **高**: `kernels` 动态下载 FlashAttention 3（`varunneal/flash-attention-3` 或 `kernels-community/flash-attn3`）—— **运行时远程加载 GPU kernel，不在 audit 范围**
  - 🟡 **中**: `rustbpe>=0.1.0` 是 Karpathy 自己的 0.x 包，API 可能变
  - 🟢 **低**: 没有外部 SaaS / HTTP 调用
- **特别提示**: `[tool.uv.sources]` 把 torch 指向 `https://download.pytorch.org/whl/cu128`，**该 URL 是 PyTorch 官方但需要主动 review**

#### 可复用经验
1. **当需要给 agent 限定可操作空间时，应优先用"文件级权限"做硬约束（如 agent 只能改 `train.py`），因为这比 prompt 里的"不要碰"更可靠，且让 agent 的 diff 自动可 review。**
2. **当评估不可控的 agent 输出时，应优先用"vocab-size-independent 指标"（如 bits-per-byte），因为 agent 会改 vocab/architecture，必须 normalize 才能公平对比。**
3. **当长任务 agent 容易"发散"时，应优先设置"快速失败"机制（如 `loss > 100 → exit(1)`），这比"让 agent 跑到自然结束"省 80% 时间，且让 crash 成为合法状态。**
4. **当需要 agent 自主迭代时，应优先分离"schedule 抽象"和"训练主循环"（如 `get_lr_multiplier(progress)` 是统一入口），让 agent 改 schedule 时不破坏主循环 invariant。**
5. **当 prompt 里"不要 X"不奏效时，应优先用代码结构 enforce（如 `prepare.py` vs `train.py` 文件分开，agent 物理上无法 import 修改后的 prepare.py）。**

#### ⭐ 源码精读（3 个代码块）

**代码块 1: `bin/gsd-tools.cjs` 的 `_dispatchNonFamily`（SDK bridge）**
```javascript
function _dispatchNonFamily({ registryCommand, registryArgs, legacyCommand, legacyArgs, cwd, raw, error, output }) {
  if (!_tryLoadSdkBridge()) return false;  // SDK 不可用 → 回退 CJS
  const result = getExecuteForCjs()({
    registryCommand, registryArgs, legacyCommand, legacyArgs,
    mode: 'json', projectDir: cwd, workstream: process.env.GSD_WORKSTREAM || undefined,
  });
  if (!result.ok) {
    const reason = result.errorDetails && result.errorDetails.reason;
    if (reason) { error(message, reason); } else { error(message); }
    return true;  // handled (error reported)
  }
  // CJS parity for --raw output
  const data = result.data;
  if (raw && (typeof data === 'string' || typeof data === 'number' || typeof data === 'boolean')) {
    output(data, raw, String(data));
  } else {
    output(data, raw);
  }
  return true;
}
```
**逻辑摘要**:
- **渐进式迁移策略**：新逻辑先在 SDK (TypeScript) 实现，CJS 旧实现保留为 fallback
- **错误结构化**：`errorDetails.reason` 是 typed reason code（如 `'config_key_not_found'`）
- **raw 输出 parity**：SDK 返回 scalar 时 `output(value, raw, String(value))` 不二次 stringify
- **永远返回 true (handled)**：即使失败也返回 true，避免 CJS 重复报错

**代码块 2: `bin/install.js` 的 Hermes 兼容逻辑**
```javascript
const HYPHEN_NAME_AGENT_RUNTIMES = new Set(['claude', 'qwen', 'hermes']);

function shouldNormalizeHyphenNamespaceInAgentBody(runtime) {
  if (typeof runtime !== 'string' || runtime === '') return false;
  return HYPHEN_NAME_AGENT_RUNTIMES.has(runtime);
}

function normalizeAgentBodyForRuntime(content, runtime, cmdNames) {
  if (!shouldNormalizeHyphenNamespaceInAgentBody(runtime)) return content;
  return transformContentToHyphen(content, cmdNames);
}
```
**逻辑摘要**:
- **Hermes 在 allow-list**：GSD 知道 Hermes namespace 是 hyphen-form（`/gsd-foo` 而非 `/gsd:foo`）
- **explicit allow-list 而非 deny-list**：未知 runtime 默认"不重写"（**防 mangling**）
- **Pure function**：`normalizeAgentBodyForRuntime` 不会改 input 除非 predicate 说改

**代码块 3: `workflows/execute-phase.md` 的核心原则**
```markdown
<core_principle>
Orchestrator coordinates, not executes. Each subagent loads the full execute-plan context. 
Orchestrator: discover plans → analyze deps → group waves → spawn agents → handle checkpoints → collect results.
</core_principle>

<runtime_compatibility>
**Subagent spawning is runtime-specific:**
- Claude Code: Uses `Agent(subagent_type="gsd-executor", ...)` — blocks until complete, returns result
- Copilot: Subagent spawning does not reliably return completion signals. Default to sequential inline execution.
- Other runtimes: If `Agent`/`agent` tool is unavailable, use sequential inline execution as the fallback.

**Fallback rule:** If a spawned agent completes its work (commits visible, SUMMARY.md exists) 
but the orchestrator never receives the completion signal, treat it as successful based on 
spot-checks and continue to the next wave/plan. Never block indefinitely waiting for a signal — 
always verify via filesystem and git state.
</runtime_compatibility>
```
**逻辑摘要**:
- **Context budget 守护**：orchestrator 不读 plan 细节（避免 context 膨胀）
- **Wave-based parallelization**：plan 间有依赖的进同一 wave
- **Spot-check fallback**：subagent 不响应时看 git/SUMMARY 文件判断
- **Never block indefinitely**：永远设上限

### 4.2 单文件可改 + 时间预算是 agent 自主实验的最佳边界（#64）
- **当让 agent 跑自主实验时，应优先用"单文件可改 + 固定时间预算"双约束**（agent 物理上无法改其他文件 + 训练时间固定 N 分钟）

### 4.3 agent harness 可观测性应分离运行时记录与健康度计算（#65）
- **当给 agent harness 装可观测性时，应优先分离"运行记录"（JSONL）和"健康度计算"（独立 dashboard 脚本）**，让 health 评估可重放、可单元测试
- **证据**: affaan-m/ECC `scripts/skills-health.js` 用 `--runs-file` 注入 JSONL，`--warn-threshold 0.1` 控制告警
- **OpenClaw 落地**: `memory/YYYY-MM-DD.md` 升级为结构化 JSONL

### 4.4 跨 runtime 的 namespace 兼容性用 explicit allow-list 表达（#66）
- **当同一份规范需要支持多个 runtime，应优先用 explicit allow-list**（`HYPHEN_NAME_AGENT_RUNTIMES = new Set(['claude', 'qwen', 'hermes'])`），未知 runtime 默认"不重写"比误改 namespace 更安全
- **证据**: gsd-build/get-shit-done `bin/install.js` 第 41-49 行明确 allow-list `'claude', 'qwen', 'hermes'`
- **OpenClaw 落地**: 未来如发布多 host skill（Hermes 主线 + 其他 harness），借鉴此模式

### 4.5 agent 长任务的稳健性来自 "filesystem + git 状态是 ground truth"（#67）
- **当设计 agent 多步骤 pipeline 时，应优先实现"subagent 完成判断不靠完成信号，靠 filesystem + git 状态"**（spot-check），因为不同 runtime 的 subagent 行为不一致
- **证据**: gsd-build/get-shit-done `workflows/execute-phase.md` 的 `<fallback rule>`: "Never block indefinitely waiting for a signal — always verify via filesystem and git state"

- **当 GitHub API 返回 license.spdx_id=NONE 时，应优先手动确认仓库根是否有 LICENSE 文件**，NONE 可能是"未设置"（默认 all-rights-reserved）而非"故意无 license"
