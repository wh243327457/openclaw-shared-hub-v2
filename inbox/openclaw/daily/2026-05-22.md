## 深读项目

### 项目 1: ultraworkers/claw-code

- **一句话判断**: Rust 实现的 AI 编程 Agent CLI 工具，史上增长最快的开源项目（4 个月破 100k stars），代表开源 Agent 的工程化新方向。
- **解决的问题**: 替代云端商业 AI 编程工具，提供本地可控制、可定制的开源方案。用 Rust 重构获得性能优势和跨平台部署能力。
- **架构/实现**:
  - 核心: `rust/` 工作空间包含 `claw` CLI 二进制
  - 使用 `oh-my-codex` 作为底层驱动（Rust 实现）
  - 支持多 provider（Anthropic/OpenAI 等）通过环境变量配置
  - `claw doctor` 健康检查命令验证 API key、模型访问、工具配置
  - 路径: 调试构建在 `rust/target/debug/claw`，发布构建在 `rust/target/release/claw`
  - Windows 下为 `claw.exe`
- **可复用经验**: 
  - 当需要构建跨平台 CLI 工具时，应优先用 Rust + 环境变量配置管理 secrets，而非硬编码或配置文件。
  - 当验证构建成功时，应提供 `doctor`/`status` 等自检命令，让用户在正式使用前发现配置问题。
- **可尝试实验**: Clone 并 build 项目，运行 `claw doctor` 验证 API key 配置，体验 Rust CLI 工具的响应速度。
- **风险边界**: 
  - License: MIT，可自由使用
  - fork/stars 比 0.57 偏高（正常应为 0.1-0.3），需关注是否存在 fork-based 增长
  - 项目较新（2026-03 创立），维护活跃度待长期观察

### 项目 2: ollama/ollama

- **一句话判断**: 本地 LLM 推理的事实标准框架，支持 10+ 主流模型（MiniMax/DeepSeek/Qwen/Gemma/Llama 等），星数达 172k，是端侧 AI 推理的入口级项目。
- **解决的问题**: 替代云端 API 调用，提供本地隐私保护、低延迟、无 API 费用的 LLM 推理能力。支持 Modelfile 定制模型行为。
- **架构/实现**:
  - 核心后端: 基于 `llama.cpp` 项目，Georgi Gerganov 主导
  - 支持模型: gemma3, llama3, qwen, deepseek, glm, minimax, mistral, gpt-oss 等
  - REST API: `http://localhost:11434/api/chat`
  - 多语言 SDK: Python (`pip install ollama`)、JavaScript (`npm i ollama`)
  - 官方 Docker 镜像: `docker pull ollama/ollama`
  - 社区集成: 50+ 界面（Open WebUI、Dify.AI、AnythingLLM 等）
- **可复用经验**:
  - 当构建 AI 推理基础设施时，应优先选择 llama.cpp 作为底层引擎，享受生态和硬件加速红利。
  - 当需要让用户快速上手时，应提供 REST API + 多语言 SDK + Docker 镜像三件套，降低门槛。
- **可尝试实验**: 安装 Ollama 后运行 `ollama run gemma3`，本地体验模型推理，对比云端 API 延迟。
- **风险边界**:
  - License: MIT，商业友好
  - 维护活跃度高（今日 push，16k forks，3270 open issues）
  - 模型权重要求较高，本地运行需足够内存（建议 8GB+）

### 项目 3: rustdesk/rustdesk

- **一句话判断**: Rust 实现的跨平台远程桌面方案，可自托管替代 TeamViewer/AnyDesk，114k stars 验证市场需求。
- **解决的问题**: 替代商业远程桌面工具，提供完全自主控制的开源方案，解决数据隐私和成本问题。
- **架构/实现**:
  - 核心语言: Rust（性能+安全）
  - GUI: Flutter（跨平台桌面/移动）或 Sciter（已废弃）
  - 协议: RDP/VNC/P2P，支持 rendezvous/relay 中继
  - 依赖: libvpx, libyuv, opus, aom（视频编解码）
  - 构建: 需要 vcpkg 管理 C++ 依赖
  - 支持平台: Windows, macOS, Linux, Android, iOS, Flatpak, F-Droid
- **可复用经验**:
  - 当需要构建跨平台实时通信应用时，应优先考虑 P2P 直连 + 中继回退的混合架构，保证在 NAT 环境下的可用性。
  - 当使用 Rust + Flutter 组合时，应通过 submodule 管理原生依赖，保持构建一致性。
- **可尝试实验**: 下载 Release 二进制，搭建本地 relay server，体验自托管远程桌面。
- **风险边界**:
  - License: AGPL-3.0，传染性较强，商业使用需注意
  - open issues 仅 117，维护状态健康
  - 构建复杂度高（需要 vcpkg + 多个 C++ 库），非 Rust 开发者入门门槛较高

## 经验沉淀

1. **"协议即中间件" 模式**: Ollama 的成功证明，当 AI 推理能力标准化后，上层应用生态自然会涌现。学习用 MCP（Model Context Protocol）等协议封装工具，可让 Agent 跨框架复用。

2. **CLI 工具的 Rust 化**: claw-code 和 RustDesk 均用 Rust 实现 CLI/桌面工具，获得性能和安全优势。当需要构建工具类软件时，Rust 是值得优先考虑的语言选择。

3. **自托管 vs 云端的权衡**: RustDesk（远程桌面）和 Ollama（本地推理）代表同一趋势——用户越来越在意数据隐私和成本控制，愿意牺牲部分便利换取自主控制权。

4. **高速增长项目的 fork 星比异常**: claw-code 的 fork/stars 比达 0.57，远超正常值（0.1-0.3），可能与项目鼓励 fork 或存在刷星现象有关，需交叉验证其他指标。
