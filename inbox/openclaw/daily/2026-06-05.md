### 1. safishamsi/graphify

**一句话判断**：把任意目录（代码 / SQL / 论文 / 视频）转成可查询知识图谱 —— 离线可用（`networkx + datasketch + tree-sitter` 零 LLM 即可跑通）、三层去重保稳定、16 个 AI host 一键安装 skill，对 OpenClaw 的"知识管理"是现成范本。

**解决的问题**：当代码库 / 文档集 / 论文夹规模超过"个人能记住"的上限（5-10K 文件），传统 RAG（向量检索）只能回答"这段代码在不在"，无法回答"AuthModule 跟 Database 怎么连"、"SwinTransformer 在哪个项目里被引用"。graphify 把 corpus 提升为图：节点 = 实体（函数 / 类 / 概念 / 论文），边 = 关系（calls / imports / cites / related-to），配合 Leiden 社区检测自然暴露"我自己都没意识到的聚类"。最关键是**离线即可用**：`pip install` 不强制拉 LLM 库，`/graphify --no-viz --no-llm` 是真的能跑出图。

```python
# 文件: build.py — _normalize_id 与三层去重
def _normalize_id(s: str) -> str:
    """Normalize an ID string the same way extract._make_id does.

    Used to reconcile edge endpoints when the LLM generates IDs with slightly
    different punctuation or casing than the AST extractor. Must stay in sync
    with extract._make_id — NFKC normalization, \w with re.UNICODE, underscore
    collapse, and casefold must all match (#811).
    """
    s = unicodedata.normalize("NFKC", s)
    cleaned = re.sub(r"[^\w]+", "_", s, flags=re.UNICODE)
    cleaned = re.sub(r"_+", "_", cleaned)
    return cleaned.strip("_").casefold()

# 节点去重 — 三层 (源自源码注释):
# 1. Within a file (AST): each extractor tracks a `seen_ids` set
# 2. Between files (build): NetworkX G.add_node() is idempotent
# 3. Semantic merge (skill): explicit `seen` set keyed on node["id"]
```

```python
# 文件: detect.py — Zip-bomb 双层防御
def _zip_within_caps(path: Path) -> bool:
    """Reject a zip-based office file that is a likely zip/XML bomb.
    
    Two layers, because the zip central-directory sizes are attacker-controlled:
    1. A cheap pre-filter on the declared sizes (on-disk cap, summed-uncompressed
       cap, compression ratio) that rejects an honest bomb without decompressing.
    2. An authoritative pass that stream-decompresses every member with a hard
       byte ceiling, so a member that under-declares its size in the central
       directory cannot expand past the cap undetected. Decompression is chunked
       and bounded, so checking a bomb never materializes more than the ceiling.
    """
    # 1) declared-size pre-check
    if not _file_within_size_cap(path):
        return False
    with zipfile.ZipFile(path) as zf:
        infos = zf.infolist()
        compressed = sum(i.compress_size for i in infos) or 1
        declared = sum(i.file_size for i in infos)
        if declared > _OFFICE_MAX_DECOMPRESSED_BYTES:  # 512 MiB
            return False
        if declared / compressed > _OFFICE_MAX_COMPRESSION_RATIO:  # 200x
            return False
        # 2) stream-decompress with hard ceiling
        total = 0
        for info in infos:
            with zf.open(info) as member:
                while True:
                    chunk = member.read(1024 * 1024)
                    if not chunk: break
                    total += len(chunk)
                    if total > _OFFICE_MAX_DECOMPRESSED_BYTES:
                        return False
    return True
```

```python
# 文件: cluster.py — Leiden 优先 + Louvain 回退
def _partition(G: nx.Graph, resolution: float = 1.0) -> dict[str, int]:
    """Run community detection. Returns {node_id: community_id}.
    
    Tries Leiden (graspologic) first — best quality.
    Falls back to Louvain (built into networkx) if graspologic is not installed.
    
    resolution > 1.0 → more, smaller communities.
    resolution < 1.0 → fewer, larger communities.
    """
    stable = nx.Graph()
    stable.add_nodes_from(sorted(G.nodes(), key=str))  # 排序保证确定性
    edge_rows = sorted(G.edges(data=True), key=lambda row: (str(row[0]), str(row[1]), ...))
    
    try:
        from graspologic.partition import leiden
        lsig = inspect.signature(leiden).parameters
        # 动态 kwargs 兼容 graspologic 各版本
        kwargs: dict = {}
        if "random_seed" in lsig: kwargs["random_seed"] = 42
        if "trials" in lsig: kwargs["trials"] = 1
        if "resolution" in lsig: kwargs["resolution"] = resolution
        # 抑制 graspologic ANSI 污染 PowerShell
        with _suppress_output():
            result = leiden(stable, **kwargs)
        return result
    except ImportError:
        pass
    # Fallback: louvain
    communities = nx.community.louvain_communities(stable, seed=42, threshold=1e-4, ...)
```

**可复用经验**：
1. **当需要把异构 corpus 转成结构化知识时，应优先采用"AST + 语义"双轨提取 + 三层去重**，因为 AST 精确但只能覆盖代码，LLM 语义可覆盖概念但会生成不一致 ID；归一化映射（NFKC + casefold）让两层数据无缝合并。边界：归一化不能跨语义等价（如 "validate" vs "is_valid" 是不同函数）。
2. **当 LLM 调用的是不受信 corpus 时，应优先对 .docx/.xlsx/.zip 类容器做"声明大小" + "流式解压"双层防御**，因为 zip 中央目录可被攻击者伪造，单纯大小检查会被 XML bomb 击穿。边界：流式解压仍有 ~50MB 内存开销，极大规模文件需换 streaming parser。
3. **当需要支持多语言函数调用分析时，应优先按文件扩展名定义 language family 并丢弃跨语言 INFERRED `calls` 边**，因为同名短函数（`render`/`parse`/`init`）在跨语言 chunk 中会形成假调用图，污染下游分析。边界：需要保留显式 `import` 边（不同语言间会显式调用）。
4. **当需要让一个工具在多 AI host 复用时，应优先用 "skill-*.md 副本 + 渐进式披露 references/" 双层结构**，因为每个 host 的 metadata 格式略不同，单一 SKILL.md 难以适配。边界：维护成本 = 16 份更新，新 host 接入需评估 ROI。

### 2. MemPalace/mempalace

**一句话判断**：**本地优先 + 零 API key + Verbatim 存储** 的 AI 长期记忆系统 —— 96.6% R@5 on LongMemEval（raw 模式）、method of loci + Zettelkasten 隐喻（Wings/Rooms/Drawers）、ChromaDB 可插拔后端、AAAK 符号压缩索引，对 OpenClaw `memory/` 模块是"工业级参考实现"。

**解决的问题**：现有 AI 记忆系统有三大痛点 —— ① 闭源 SaaS 数据外泄（Mem0 / Zep）；② 强制 API key 门槛（LangChain Memory）；③ 一旦总结就丢失原话（绝大多数"智能记忆"）。MemPalace 的硬承诺是 **100% 召回 + 永远 verbatim**：用户说的每个字都按原样存（drawers），索引层用 AAAK 符号压缩（closets）做"快速寻找哪一格打开"，搜索时**永远直接打开 drawer 拿到原话**，不存在"AI 总结后给你看"。这与 `SOUL.md` 的"私人信息不外泄 + 真相不篡改"哲学完全同构。

### 3. esengine/DeepSeek-Reasonix

**一句话判断**：把"prefix-cache 稳定"当作一等公民的 DeepSeek-native AI 编码 agent —— 109KB TUI + 双 Session Coordinator（planner + executor）+ PrefixShape 哈希诊断 + 软/硬压缩比分层 + 32KB 工具输出截断，把 cache hit rate 做成"显式可观测的工程目标"，是工业级 Go agent 工程的范本。

**解决的问题**：主流 AI agent 工具（Claude Code / Cursor / Aider）在长任务中普遍遇到"上下文涨到 80% → 触发 compact → 整个 prefix cache 全部失效 → 下一轮重新计算 prompt-cache → token 成本突然 ×10" 的痛点。Reasonix 的解法是把 cache 当作"显式可观测的工程对象"：
- 用 **PrefixShape 哈希**（system + tools + log_rewrite_version）精确诊断"为什么这一轮 cache miss 了"
- 用 **双 Session Coordinator** 让 planner 和 executor 各持独立 session，**互不污染** prefix
- 用 **soft (0.5) / hard (0.8) / force (0.9) 压缩比**分层，让"软警告但保留 cache"和"硬压缩但 cache 重建"分清楚
- 用 **32KB 工具输出截断**（≈8K tokens）防止"read this 5MB log"一次性炸毁窗口

```go
// 文件: internal/agent/cache_shape.go — PrefixShape 哈希 + 诊断
// PrefixShape hashes the portions of the request prefix that influence
// provider-side prompt-cache reuse. Comparing snapshots across turns
// lets us explain *why* a cache miss happened.
type PrefixShape struct {
    SystemHash        string
    ToolsHash         string
    PrefixHash        string
    LogRewriteVersion int
    ToolSchemaTokens  int
}

func CaptureShape(systemPrompt string, schemas []provider.ToolSchema, rewriteVersion int) PrefixShape {
    normalizedSchemas := normalizeToolSchemas(schemas)  // 关键: 先排序
    toolsJSON, _ := json.Marshal(normalizedSchemas)
    return PrefixShape{
        SystemHash:        shortHash(systemPrompt),
        ToolsHash:         shortHash(string(toolsJSON)),
        PrefixHash:        shortHash(map[string]interface{}{"system": systemPrompt, "tools": string(toolsJSON)}),
        LogRewriteVersion: rewriteVersion,
        ToolSchemaTokens:  estimateTokens(string(toolsJSON)),
    }
}

// CompareShape returns diagnostics describing what changed between two shapes.
func CompareShape(prev, cur PrefixShape, usage *provider.Usage) CacheDiagnostics {
    reasons := []string{}
    if prev.SystemHash != "" && prev.SystemHash != cur.SystemHash {
        reasons = append(reasons, "system")
    }
    if prev.ToolsHash != "" && prev.ToolsHash != cur.ToolsHash {
        reasons = append(reasons, "tools")
    }
    if prev.LogRewriteVersion != cur.LogRewriteVersion {
        reasons = append(reasons, "log_rewrite")
    }
    return CacheDiagnostics{...}
}

// 关键设计:
// 1. Tool schema 排序后再 hash — 因为 provider 端 tools 数组顺序影响 prefix 哈希
// 2. estimateTokens 用 byte/4 近似 — 对诊断够用,零 alloc
// 3. CompareShape 输出 reasons 数组,让 UI 能精确告诉用户 "为什么 miss"
```

```go
// 文件: internal/agent/coordinator.go — 双 Session 协调
// Coordinator runs two models in separate sessions to keep each one's prompt
// prefix cache-stable: a low-frequency planner proposes an approach, then the
// executor (a full tool-using Agent) carries it out. The sessions never mix,
// so neither model's prefix is disturbed by the other's turns.
type Coordinator struct {
    planner        provider.Provider
    plannerSess    *Session    // 独立 session
    plannerPricing *provider.Pricing
    executor       *Agent      // 独立 session
    temperature    float64
    sink           event.Sink
    // shouldPlan gates the planner pass per turn; nil plans every turn.
    // Lets a trivial, non-work turn (a question, a greeting) skip straight
    // to the executor instead of paying a planner round on it.
    shouldPlan func(string) bool
}

func (c *Coordinator) Run(ctx context.Context, input string) error {
    c.sink.Emit(event.Event{Kind: event.TurnStarted})
    // shouldPlan gate: trivial 任务直接进 executor
    if c.shouldPlan != nil && !c.shouldPlan(input) {
        c.sink.Emit(event.Event{Kind: event.Phase, Text: c.executor.prov.Name() + " · executing"})
        return c.executor.Run(ctx, input)
    }
    c.sink.Emit(event.Event{Kind: event.Phase, Text: c.planner.Name() + " · planning"})
    plan, err := c.plan(ctx, input)
    if err != nil { return fmt.Errorf("planner: %w", err) }
    c.sink.Emit(event.Event{Kind: event.Phase, Text: c.executor.prov.Name() + " · executing"})
    return c.executor.Run(ctx, formatHandoff(input, plan))
}

// 关键: 两个 session 物理隔离 → planner 加 plan 不污染 executor prefix
// plan stream 直接追加到 planner session,prepend-only 保持 cache-friendly
```

```go
type Tool interface {
    Name() string
    Description() string
    Schema() json.RawMessage
    Execute(ctx context.Context, args json.RawMessage) (string, error)
    // ReadOnly reports whether the tool has no observable side effects on the host.
    // The agent parallelises a batch of tool calls only when every call in the
    // batch is ReadOnly; mixed batches stay sequential so write/read ordering
    // is preserved. bash and plugin tools must return false because their
    // effects can't be inferred statically from args.
    ReadOnly() bool
}

// Previewer is an optional capability a writer Tool may implement: given the
// same raw JSON args Execute would receive, compute the file change the call
// *would* make — without touching disk. A front-end uses it to show an
// approval card or a changed-files panel before the call runs.
type Previewer interface { Preview(args json.RawMessage) (diff.Change, error) }

// --- process-global built-in set (populated by builtin subpackage init) ---

// RegisterBuiltin registers a compile-time built-in tool. Intended for init().
// It panics on a duplicate name, which is a compile-time wiring mistake.
func RegisterBuiltin(t Tool) {
    name := t.Name()
    if _, dup := builtins[name]; dup {
        panic("tool: duplicate built-in " + name)
    }
    builtins[name] = t
}

// Registry is a per-run set of tools: enabled built-ins plus plugin tools.

    tools map[string]Tool
    order []string      // first-seen 顺序
    canon map[string]json.RawMessage  // canonicalized schema
}
```

**依赖分析**：
- **核心**：`charm.land/bubbles/v2`（TUI 组件）、`charm.land/bubbletea/v2`（TUI 框架）、`charm.land/lipgloss/v2`（终端样式）、`BurntSushi/toml`、`alecthomas/chroma/v2`（语法高亮）、`yuin/goldmark`（Markdown 渲染）、`sabhiram/go-gitignore`、Go 标准库
- **测试**：`go.uber.org/goleak`（goroutine 泄漏检测）、`golang.org/x/{net,term,text,sys}`
- **Go 工具链**：`go 1.25.0` + `toolchain go1.26.4`（最新）
- **供应链风险**：
  - **charm.land 命名空间风险**：`charm.land/bubbles/v2` 等是 Charmbracelet 的新 import 路径（替代 `github.com/charmbracelet/bubbles`），生态较新、v2 仍可能调整
  - **Go 1.26 toolchain 要求**：很多 CI 镜像默认 go ≤ 1.24，需手动指定
  - **OpenAI/Anthropic SDK 间接依赖**（未在 go.mod 顶部，但代码引用）：评估时需补全
  - **进程外 plugin transport**（stdio + HTTP）扩大攻击面（一个挂了不影响主进程，但写文件权限边界需注意）

**可复用经验**：
1. **当需要 LLM agent 长任务时，应优先把 prefix-cache 稳定作为一等公民设计**：用 SHA256 哈希 (system + tools) 作为 PrefixShape，每次请求后 CompareShape 输出 `["system", "tools", "log_rewrite"]` reasons，让用户/UI 能精确看到"为什么这一轮 cache miss"。边界：估计 token 用 byte/4 足够诊断用，但生产计费需真实 tokenizer。
2. **当 agent 需要 plan + execute 分离时，应优先用物理隔离的 session 而非同一 session 内分角色**，因为 plan 的 system_prompt 与 execute 的 tool schema 不一样，混在同 session 必然引起 prefix cache 失效。Reasonix 的 Coordinator 模式 + `shouldPlan` gate 让"trivial 任务跳过 planner"也优雅。
3. **当需要三层压缩（软/硬/强制）时，应优先用固定 token 预算而非窗口比例**，因为 50% 的"巨窗口"等于"永不压缩"，50% 的"小窗口"等于"反复压缩"，固定 token 数（默认 16384 tail budget）让两种场景都稳定。边界：极小窗口（< 16K）下 minRecentKeep=2 兜底。
4. **当需要把"工具副作用"分级时，应优先让 Tool 接口暴露 `ReadOnly()` 而非每次都问权限系统**，因为只读工具可并行批处理，副作用工具必须串行；`Previewer` 可选接口让"写工具先 preview 再执行"成为标准模式，UI 提前展示 diff 卡片。边界：bash/plugin 工具无法静态推断，必须 ReadOnly=false。
5. **当需要进程外扩展时，应优先 interface 化（Renderer/Asker/Gate/ToolHooks）+ nil 兜底**，因为 headless 测试需要能跳过所有前端，nil 解释为"未配置，自动 fallback"。边界：nil 检查不能完全避免运行时 panic，关键路径用 `nilutil.IsNil` 显式处理（`internal/nilutil` 子包存在本身就是证据）。

## 经验沉淀

> 当……时，应优先……，因为……，边界是……

1. **当需要让 corpus → 知识时，应优先采用"AST + 语义"双轨 + 三层去重**（graphify 模式），因为 AST 精确但只覆盖代码、LLM 语义广但 ID 不一致；归一化映射（NFKC + casefold）让两层数据无缝合并。边界：跨语义等价（"validate" vs "is_valid"）不能被归一化吃掉。

2. **当 corpus 来自不可信源时，应优先对 zip 容器做"声明大小 + 流式解压"双层防御**（graphify `_zip_within_caps`），因为攻击者可伪造 zip 中央目录大小，单层 size check 会被 XML bomb 击穿。边界：流式解压仍有 ~50MB 内存开销，极大规模需 streaming parser。

3. **当 LLM agent 长任务中需要压缩时，应优先把"压缩"做成"软警告 / 硬压缩 / 强制压缩"三层 + 固定 token 预算**（Reasonix `compact.go`），因为比例式触发在小窗口下会反复压缩、巨窗口下永不压缩。边界：极小窗口（< 16K）需 `minRecentKeep=2` 兜底。

4. **当 LLM agent 跨多阶段时（plan + execute），应优先物理隔离 session 而非同 session 切角色**（Reasonix `Coordinator`），因为 plan 和 execute 的 system/tool schema 不一样，混在同 session 必然引起 prefix-cache 失效。边界：需要 `shouldPlan` gate 跳过 trivial 任务。

5. **当需要诊断 LLM 成本/性能时，应优先把 prefix-cache 哈希 + 变化原因做成显式可观测对象**（Reasonix `cache_shape.go`），因为"为什么 miss"是调优起点；用 `["system", "tools", "log_rewrite"]` 分类让 UI 精确显示。边界：byte/4 估算 token 对诊断够用，生产计费需真 tokenizer。

6. **当 AI 工具接入多 host（Claude Code / Cursor / Codex / OpenClaw）时，应优先采用 "skill-*.md 副本 + 渐进式披露 references/"**（graphify 16 份 skill），因为每个 host 的 frontmatter 格式略不同，单一文件难适配。边界：维护成本 = 16 份更新，需评估新 host ROI。

7. **当设计 AI 记忆系统时，应优先承诺 "100% 召回 + verbatim 存储" 而非 "智能总结"**（MemPalace `CLAUDE.md` 设计原则），因为任何总结都意味着用户原话不可恢复，与"记忆是身份"哲学冲突。边界：closet/索引层可以有损，drawer/存储层必须 verbatim。

8. **当 ChromaDB EF 替换/升级时，应优先关注 `name()` 标签身份**（MemPalace `embedding.py`），因为 ChromaDB 1.5 持久化 EF 身份、跨 EF 读会被拒，欺骗 name tag 比重建 collection 简单。边界：向量空间变了必须 rebuild-index，name 相同救不了语义不兼容。

9. **当 MCP server 启动时，应优先用 `os.dup2(2, 1)` 强制 stderr-only 日志**（MemPalace `mcp_server.py:25-43` 修复 #225），因为 chromadb/onnxruntime 等依赖会向 stdout 写 banner，破坏 JSON-RPC 协议。边界：Windows 某些 Python embed 没有 fd-level，需 Python 级 redirect 兜底。

10. **当 AI 工具需要"无 API key 也能工作"时，应优先走 stdlib `urllib` 调 OpenAI 兼容 endpoint 而非 `openai` SDK**（MemPalace `closet_llm.py` 零依赖设计），因为 SDK 强制引入 httpx 等大依赖、且版本要求严苛。边界：URL scheme 必须强校验 `http(s)://`，拒 `file://` 防止本地文件外泄。
