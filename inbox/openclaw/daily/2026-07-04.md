### 3.1 Kulaxyz/self-learning-skills

**Stars: 790 · License: MIT · Language: (skill only) · Created: 2026-06 (近 7 天) · Pushed: 2026-07-01**

#### 项目概述

`self-learning-skills` 是一个 **Agent 自进化 meta-skill** —— 它不解决具体业务问题，而是教 Agent 识别"刚刚走通的 golden path"，并把它自动沉淀到下一个 session 能自动加载的位置（Claude Code/Codex 的 `skills/<name>/SKILL.md`、Cursor 的 `.cursor/rules/learned/<name>.mdc`、或者纯 `AGENTS.md`）。它的核心价值在于把"硬抢来的运维知识（DB 怎么连、creds 在哪、deploy 命令、迁移 dance）"从 session-local 蒸发变成 *auto-loadable next time*。

它也是少有的、把"显式教学 Agent 何时该停止 -> 沉淀 -> 沉淀到哪 -> 沉淀什么粒度"整套规范都写死的 skill。

#### 关键源码文件分析

**`skills/self-learning/SKILL.md` — meta-skill 主定义**（约 250 行）

frontmatter 直接把所有触发信号写到 `description` 字段，让 Agent description-match 时能命中：

```yaml
description: >
  Capture a hard-won "golden path" from the current session as a reusable Agent
  Skill, so future sessions start already knowing it. Use it (1) right after
  non-trivial debugging, after working out a multi-step operational workflow, or
  after rediscovering project facts you didn't know up front — e.g. how to reach
  the dev/prod database, where credentials and env vars live, how to deploy, run
  migrations, or verify a change live; and (2) whenever the user says "remember
  this", "save this as a skill", "make a skill for this", "don't make me
  re-explain this next time", or otherwise wants a workflow preserved across
  sessions.
```

注意它的 description 里 *显式列出了具体场景*（reach DB / creds / deploy / migrations / verify live）—— 这是 Agent Skills 协议的设计：description 是 trigger，不是简介。

**核心三段 — Promotion Rule（这是整个 skill 最值钱的地方）**：

> Only promote a session to a durable entry when **all three** hold:
> 1. **A passing check** — the path was actually verified (a test passed, the command exited clean, the repro reproduced, the build went green). Record it. "Seemed to work" doesn't count.
> 2. **A named failure pattern** — you can name the failure it avoids or diagnoses, not a vague "sometimes it breaks".
> 3. **At least one ruled-out dead-end** — a concrete approach you tried and eliminated, with the reason.

这条规则直接回答了 Agent 自我进化的核心矛盾：什么时候该相信自己的总结？答案是"全部满足才信"——这样 confident guess 就进不了 skill 库。

**Triage — 决定粒度而不是置信度**：

```markdown
| Lesson | Where it goes |
|---|---|
| A multi-step, reusable **procedure/workflow** | a new skill / rule |
| A single **fact or one-line correction** | lightweight notes/memory (e.g. a `MEMORY.md`) |
| A genuine **one-off** | skipped |
```

这条直接解决了我自己用 Hermes 时遇到的痛点：把一个 one-line fact 写成 skill 会污染 description-match 索引，必须有 triage gate。

**Secret 安全硬约束**（这是安全边界最关键的一行）：

> **Secrets never go in a skill file.** Skills get committed and open-sourced.
> Point to *where* the secret lives; never reproduce the value.

#### 架构/实现原理

整个 skill 的"运行时"完全靠 Agent 自己跑——没有 daemon、没有数据库。流程是：

```
Agent 工作 session
    │
    ▼ (监测到 trigger signal)
Recognize the moment:
  - 多次重试才成功
  - 发现项目特有的事实（env var、selector、非显然命令、gotcha）
  - 重复性运维工作流（DB/deploy/migration/verify）
  - 用户明确说 "remember this"
    │
    ▼
Apply Promotion Rule (passing check + named failure + ruled-out dead-end)
    │
    ├─ 任意一条不满足 → 写 tentative memory note (标 unverified) 或跳过
    │
    └─ 三条都满足 → 进入 Harvest Procedure:
        1. Apply promotion rule (再次确认)
        2. Choose scope/name yourself (project 默认, 名字 lowercase-a-z/0-9/-)
        3. Dedupe (扫已有 skills/rules/memory, 更新而非新建)
        4. Distill golden path from THIS conversation (趁新鲜)
        5. Delegate to subagent (带 context: fork, 避免新鲜 agent 空白)
        6. Relay path to user
    │
    ▼
Persist to auto-load location:
  - Claude Code / Codex → skills/<name>/SKILL.md
  - Cursor → .cursor/rules/learned/<name>.mdc
  - Others → AGENTS.md / project notes
    │
    ▼
Next session auto-loads by skill description match (skills/*) 或 always-read (AGENTS.md)
```

**委派 subagent 的 brief 模板**（防止 subagent 越权）：

```markdown
> You are harvesting a skill. Your ONLY job is to write a new Agent Skill
> capturing the golden path we just worked out in this conversation:
> **[one-line description of the workflow]**.
>
> Hard rules:
> - Write ONLY under `[skills dir]/[skill-name]/`. Do NOT modify project
>   source, run builds, install anything, or resume the original task.
> - First read `[this-skill-dir]/references/skill-authoring.md` and
>   `[this-skill-dir]/assets/SKILL.template.md`, then author `SKILL.md` to that
>   spec, plus any `references/` or `assets/` files the procedure warrants.
> - Capture the PROCEDURE — commands, paths, the required order, gotchas — not a
>   one-off answer. Generalize so it works next time.
> - Capture the FAILURES too...
> - NEVER write secret VALUES (passwords, tokens, connection strings, API keys).
>   Record only WHERE to find them...
```

注意 brief 里**显式禁止 subagent 回到原任务**——这是因为 subagent 默认会"顺手干完"，必须有硬栅栏把它限制在 skills dir。

**`src/claude_real_video/core.py` — 单 pass 帧提取**（核心函数 1）

```python
def extract_frames(video: str, frames_dir: str, scene: float, fps_floor: float) -> int:
    """One chronological pass: every scene change OR one frame per `fps_floor`
    seconds, whichever comes first. A single select filter keeps the frames in
    time order, so dedup compares true neighbours (two passes used to interleave
    scene_/floor_ files out of order). Returns the extracted count."""
    os.makedirs(frames_dir, exist_ok=True)
    every_n = max(1, round(_fps(video) * fps_floor))
    _run(["ffmpeg", "-i", video,
          "-vf", f"select='gt(scene,{scene})+not(mod(n,{every_n}))',scale=640:-1",
          "-vsync", "vfr", os.path.join(frames_dir, "raw_%05d.jpg"),
          "-hide_banner", "-loglevel", "error"])
    return len(glob.glob(os.path.join(frames_dir, "raw_*.jpg")))
```

注意 `select='gt(scene,{scene})+not(mod(n,{every_n}))'` —— **单 select 表达式融合 scene-change detection 和 fps floor**，保证输出帧按时间顺序排列（之前两个独立 pass 会乱序，dedup 失效）。这是非常细的工程 insight。

**`dedup_frames()` — sliding-window dedup**（核心函数 2）

```python
def dedup_frames(frames_dir: str, threshold: float = 8, window: int = 4,
                 max_frames: int = 150,
                 dropped_dir: str | None = None) -> tuple[int, list[dict]]:
    """Drop near-duplicate frames by real pixel difference (downscaled grayscale,
    like videostil's pixelmatch approach — more faithful than a perceptual hash,
    which goes blind on flat colours and brightness-only changes) against a
    sliding window of the last `window` kept frames. The window also catches
    A-B-A alternation — a shot the model has already seen doesn't come back
    just because a different frame sat in between.
    """
    frames = sorted(glob.glob(os.path.join(frames_dir, "*.jpg")))
    try:
        from PIL import Image
    except ImportError:
        return len(frames), []

    def sig(path: str, size: int = 16) -> list[tuple[int, int, int]]:
        # RGB, not grayscale: hues with equal luma (a red→green cut) must not
        # look identical to the comparator
        return list(Image.open(path).convert("RGB").resize((size, size)).getdata())

    def pct_diff(a: list, b: list, tol: int = 25) -> float:
        changed = sum(max(abs(x[0] - y[0]), abs(x[1] - y[1]), abs(x[2] - y[2])) > tol
                      for x, y in zip(a, b))
        return 100.0 * changed / len(a)

    kept: list[str] = []
    recent: list[list[int]] = []  # signatures of the last `window` kept frames
    records: list[dict] = []
    for f in frames:
        h = sig(f)
        dist = min((pct_diff(h, k) for k in recent), default=None)
        if dist is None or dist > threshold:
            kept.append(f)
            recent.append(h)
            if len(recent) > window:
                recent.pop(0)
            ...
```

三处工程 insight：
1. **用 RGB 而非灰度比较** —— 防止"亮度相同但 hue 不同"的镜头切换被判为重复（红→绿切换视觉差异巨大但灰度一致）。
2. **sliding window 而非 pairwise** —— 解决 A-B-A 镜头：之前见过的镜头即使中间隔了别的帧也不会重复出现。
3. **cap 在 dedup 之后** —— 先保证语义独立的帧，再均匀采样到 max_frames，保证覆盖全片。

**`_run()` / `_have()` 极简 subprocess wrapper**（5 行）：

```python
def _run(cmd: list[str]) -> subprocess.CompletedProcess:
    return subprocess.run(cmd, capture_output=True, text=True)

def _have(tool: str) -> bool:
    return shutil.which(tool) is not None
```

不引入额外依赖（subprocess.run 已经够用），符合 "core only numpy" 的极简哲学。

### 3.3 offchainthoughts/Amber

**Stars: 206 · License: MIT · Language: Python · Created: 2026-06 · Pushed: 2026-06-28 · 配套论文 `paper/amber.pdf`**

#### 项目概述

`Amber` 解决 RAG 系统的"信任危机"：我拿到了一个离线向量库 `.amber` 文件，里面说"这 100 万条 chunk 的 embedding 是用 sentence-transformers/all-MiniLM-L6-v2 算的"，我凭什么信？

论文 `paper/amber.pdf`（159 KB）给出了完整形式化证明（soundness bound、threat model、quantization 鲁棒性）。

#### 关键源码文件分析

**`amber/merkle.py` — domain-separated Merkle 树**（核心）

```python
LEAF_TAG = b"\x00"
NODE_TAG = b"\x01"

def _h(*parts: bytes) -> bytes:
    m = hashlib.sha256()
    for p in parts:
        m.update(p)
    return m.digest()

def leaf_hash(index: int, total: int, payload: bytes) -> bytes:
    """Hash a leaf, binding its index and the sequence length."""
    return _h(LEAF_TAG,
              index.to_bytes(8, "big"),
              total.to_bytes(8, "big"),
              len(payload).to_bytes(8, "big"),
              payload)

def _node_hash(left: bytes, right: bytes) -> bytes:
    return _h(NODE_TAG, left, right)
```

关键工程决策：
1. **LEAF_TAG / NODE_TAG 域分离** —— 防止 Merkle second-preimage attack（攻击者不能把 leaf 重新解释为 internal node）。
2. **leaf hash 绑定 index 和 total** —— 固定位置和序列长度，防止"把 chunk 1 的向量换成 chunk 2 的"攻击。
3. **奇数层 promote 策略** —— `right = cur[i + 1] if i + 1 < len(cur) else cur[i]`。

**`amber/artifact.py` — .amber 容器格式**（核心）

```python
FORMAT = "amber/1"
SEP = b"\x1f"  # unit separator between chunk bytes and vector bytes

def _leaf_payload(chunk: Chunk, qvec: np.ndarray) -> bytes:
    return chunk.canonical_bytes() + SEP + qvec.tobytes()

# 两个独立的 merkle root：
# 1. merkle_root 绑定 (chunk, vector) 对 → embedding fidelity
# 2. corpus_root  只绑定 chunk → corpus identity
```

**关键 insight：两个独立的 Merkle root**。这是论文 section 4 的核心贡献 —— 让"语料身份"和"embedder 忠诚度"可以独立验证：换 embedder 不影响 corpus_root，但会暴露 merkle_root 失配。

容器是 zip：`manifest.json + chunks.jsonl + vectors.i8.npy`。

**`amber/verify.py` — O(n) integrity vs O(k) audit**（核心）

```python
def verify_integrity(artifact: Artifact) -> bool:
    """Recompute roots from stored data; compare to the manifest."""
    leaves = _build_leaves(artifact.chunks, artifact.qvectors)
    if merkle_root(leaves).hex() != artifact.manifest["merkle_root"]:
        return False
    corpus = _corpus_leaves(artifact.chunks)
    return merkle_root(corpus).hex() == artifact.manifest["corpus_root"]


def audit(artifact: Artifact, embedder, k: int = 32, tolerance: int = 2,
          rng: Optional[np.random.Generator] = None,
          hypothesize_rho: Optional[float] = None) -> AuditReport:
    """Re-embed k random chunks and compare to the committed vectors.

    ``tolerance`` is the maximum allowed per-component absolute deviation in
    int8 units (absorbs benign floating-point nondeterminism for semantic
    backends; for the deterministic HashEmbedder, deviation is 0).
    """
    n = len(artifact.chunks)
    if n == 0:
        return AuditReport(sampled=0, tolerance=tolerance)
    if embedder.config_hash() != artifact.manifest["embedder_config_hash"]:
        raise ValueError("embedder config does not match the pinned manifest")

    k = min(k, n)
    # Cryptographically strong, unbiased sample without replacement.
    if rng is None:
        idx = _secure_sample(n, k)
    else:
        idx = list(rng.choice(n, size=k, replace=False))

    texts = [artifact.chunks[i].text for i in idx]
    recomputed = quantize(embedder.embed(texts))
    ...
```

**核心 insight：integrity ≠ authenticity**。
- `verify_integrity` 只检查文件内部一致性 —— **可以被自洽的伪造骗过**。
- `audit` 用 pinned embedder 重新 embed 采样 chunk —— **自洽伪造也跑不掉**。

README 的 demo 完美演示：

```
4. Forgery: vectors replaced, then RE-COMMITTED
integrity   : True   <- passes, the forgery is self-consistent
audit FAIL: sampled 3, mismatches 2, max |dev| 127 (tol 2)   <- audit catches it
```

## 4. 经验沉淀

**当设计 Agent 的 self-improving skill 时，应优先实现"promotion rule"三件套（passing check + named failure pattern + ruled-out dead-end），不要相信 summary 本身。** `self-learning-skills` 的核心 insight：confident guess 是 skill 库最大的污染源；只有可验证（test passed / cmd exited clean）+ 可定位（named failure）+ 已排除替代方案（dead-end with reason）三件齐备的总结才允许晋升为 skill。这条直接解决 Hermes 当前 `skill_manage` 靠 creator-judgement 沉淀导致的部分 skill 实际是 brittle / out-of-date 的问题。

**当实现 LLM 视频/音频理解管线时，应优先采用"scene-change detection + sliding-window dedup"而非固定 fps 采样。** `claude-real-video` 的实验数据：58 秒视频从 58 帧压到 26 帧（去 55%），且不漏快速切换。三个工程细节：①单 ffmpeg select 表达式 `gt(scene,X)+not(mod(n,K))` 融合两路采样保持时间序；②用 RGB 而非灰度比较避免 hue-only 变化被误判；③dedup 在 cap 之前保证语义独立帧优先。这套模式可推广到所有"连续帧/事件流"内容压缩场景，不限于视频。

**当需要可信离线资产（RAG 向量库、知识图谱、模型权重）时，应优先实现"密码学承诺 + 概率审计"双层验证，不要只做内部一致性检查。** Amber 的核心 insight：Merkle root 验证 integrity O(n) 即可，但无法防自洽伪造；必须额外提供 `O(k)` 概率审计（采样 k≪n 重 embed 比对）才能检测 embedder 偷懒。两个独立 root（chunk-only 和 chunk+vector）解耦语料身份和 embedder 忠诚度是教科书级设计。detection bound `1 − (1−ρ)^k` 让审计成本和信任强度可量化权衡。这条直接适用于 Hermes 的 audit-feedback.json 长期可验证化。

**当 prompt 涉及多 agent 协作（subagent / delegate）时，应优先在 brief 中显式禁止 subagent 回到原任务，并加秘密值硬约束。** `self-learning-skills` 的 subagent brief 显式写 `Do NOT modify project source, run builds, install anything, or resume the original task` —— 这是因为 subagent 默认会"顺手干完"，必须有硬栅栏。同理 `NEVER write secret VALUES (passwords, tokens, ...)` 是防止 subagent 把凭证误写到 skill 引用文件。这两条可直接移植到 Hermes 的 `delegate_task` brief 模板。
