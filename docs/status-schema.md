# 状态字段规范

共享中台 v2 的状态文档需要区分“基础设施完成度”和“治理运营成熟度”，避免一个 100% 掩盖后续运营待办。

## 推荐字段

每个 `curated/memory/projects/*.md` 项目状态页建议包含：

```markdown
## 项目概览

- 状态：绿 / 黄 / 红
- 当前阶段：基建完成 / 治理运营 / 收口 / 暂停
- 基础设施完成度：0-100%
- 治理运营成熟度：0-100%
- 最近整理时间：ISO8601 时间
```

## 字段含义

- 状态：当前风险色。
- 当前阶段：项目处于哪个主阶段。
- 基础设施完成度：目录、兼容桥、脚本、配置引用等硬结构是否完成。
- 治理运营成熟度：晋升协议、verify 治理校验、future-agent 接入、runtime retention、状态一致性等运营能力是否完成。

## 判定建议

- 基础设施 100%：可以表示 shared v2 本地结构已经可用。
- 治理运营低于 100%：表示仍有改进项，不等同于系统不可用。
- 状态为绿：允许存在 P1/P2 待办，但不能存在影响主路径的 P0 阻塞。
- 状态为黄：存在 P0/P1 风险，但解决路径明确。
- 状态为红：关键依赖缺失，或无用户决策无法继续。

## 禁止写法

- 只写“完成度 100%”，不说明是哪一层完成。
- 把未验证的计划项写成已完成。
- 把运行时日志或猜测当作项目状态。
