# 2026-05-17 — 自主学习推送可读性修正

## 触发信号

用户反馈 autonomous-learning cron 推送“消息格式太乱，看不清楚说的什么”。这属于一等 skill 信号：不是只在 memory 里记录偏好，而是要修正负责该类任务的报告/通知协议。

## 应用范围

适用于 autonomous-learning / research / cron 报告 / 多 agent 闭环结果通知，尤其是微信等窄屏聊天渠道。

## 修正后的报告原则

1. **10 秒可扫读**：开头必须先给结论，不要先解释执行细节。
2. **固定分区**：计划、执行、审计、结果、收获、下一步、需要你决策、产出文件。
3. **表格承载核心状态**：学习项、执行方、状态、审计分、晋升决策用表格；不要用长 bullet 串联。
4. **文件清单后置且限量**：最多 5 条相对路径，超过只给目录入口。
5. **内部机制不要推给用户**：不要在最终推送里写 cron 自动投递、send_message 禁用、长状态机、工具内部异常堆栈。
6. **降级/失败要人话说明**：例如“子 agent 超时，本轮仅做到 README/API 级 fallback，未源码级深读”。不要贴 `EXECUTOR_FAILED -> ...` 长状态链。
7. **决策单列**：如果需要用户拍板，单独列“需要你决策”表格；没有就明确写“暂无需要你决策的事项”。

## 推荐微信格式

```markdown
📚 **自主学习系统 — 本轮学习报告**

**时间**: YYYY-MM-DD HH:mm
**结论**: ✅ 正常 / ⚠️ 降级完成 / ❌ 失败

**📋 本轮学了什么**
| 类型 | 主题 | 为什么学 |
|---|---|---|
| GitHub/工程热点 | `<repo_or_topic>` | <一句话> |
| 非 GitHub | <topic> | <一句话> |

**🤖 执行情况**
| 学习项 | 执行方 | 状态 | 备注 |
|---|---|---|---|
| <item> | <agent/executor> | ✅/⚠️/❌ | <一句话边界> |

**🔍 审计结果**
| 学习项 | Spec | Quality | 晋升 |
|---|---|---|---|
| <item> | ✅ PASS / ❌ FAIL | <score>/20 | runtime only / 待确认 / archived |

**📊 结果沉淀**
- 产出：<一句话>
- 决策：<是否进 curated；默认不自动晋升>
- 风险：<一句话；无则写暂无明显风险>

**💡 对你有用的收获**
1. **<短标题>**：<可复用结论>
2. **<短标题>**：<工程/系统启发>
3. **<短标题>**：<失败教训或下一步改进>

**🎯 下一步**
1. <明确动作>
2. <明确动作>

**需要你决策**
暂无需要你决策的事项。

**产出文件**
- `agent-outputs/<file>.md`
- `reviews/<file>.md`
- 其他详见：`runtime/hermes/autonomous-learning/`
```

## 同次会话落地动作

- 更新 autonomous-learning notification 模板。
- 更新 autonomous-learning cron prompt，使后续自动推送强制使用可扫读格式。
- 补写一份 readable 示例报告。
- 把 bounded subagent 预算写入 orchestrator protocol：普通日报/小时学习 0–1 个，高价值 canary 1–2 个，重大跨系统决策最多 2–3 个。

## 可复用教训

当用户指出“格式乱/看不清”时，不要只重写当前消息；必须找到产生该消息的模板、cron prompt 或报告 skill，并把版式约束写进去。
