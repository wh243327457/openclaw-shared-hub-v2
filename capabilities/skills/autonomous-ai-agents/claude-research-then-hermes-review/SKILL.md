# Claude Code 首轮调研 + Hermes 二轮复核

## 何时使用

出现以下任一情况，就默认启用本 skill：
- 用户要我做调研、综述、对比、最佳实践、规则提炼、SOP/skill 沉淀
- 答案依赖用户未提供的外部网页、官方文档、README、博客或当前事实
- 需要同时阅读多个来源，再形成规则、建议、判断或流程
- 最终输出不是单一事实，而是 grounded 结论、清单、模板、评审标准
- 任务需要最新版本信息或外部可核验证据

## 不触发

以下情况一般不必强制使用：
- 纯本地代码修改、测试、脚本执行
- 用户已提供全部材料，且无需外部补查
- 单一、低歧义的外部事实核验，且不需要系统性综述

## 核心原则

1. 角色分离
   - Hermes 负责界定任务、委派、验收、复核、最终答复。
   - Claude Code 负责首轮外部资料抓取、阅读、摘录、初步综合。

2. 先委派，后综合
   - 对外部调研型任务，Hermes 不先读主要外部来源，不先形成首轮结论。

3. Claude 交“研究包”，不是直接交“终稿”
   - 至少要有：来源清单、关键启发/摘录、初步规则、断言映射、未决问题。

4. Hermes 复核研究包，不复述研究包
   - 先回看 Claude 已引用来源，抽查关键断言，再决定是否需要定向返工。

5. 发现自己已先做主要研究，就承认流程被污染并重置
   - 不能把后续委派包装成真委派。

## 标准流程

### 第 1 步：判定是否为外部调研型任务
只基于：
- 用户请求
- 当前本地上下文
- 已提供材料

不要在这一步先去读主要外部来源。

### 第 2 步：冻结自己的首轮外查
一旦判定为外部调研型任务，Hermes 在委派前只允许做：
- 解析用户目标
- 提炼验收标准
- 设计输出结构
- 准备候选来源范围或来源类型要求

Hermes 不允许做：
- 打开主要目标来源并完成首轮阅读
- 先写自己的研究结论
- 先产出规则草案，再让 Claude Code 去补依据

### 第 3 步：给 Claude Code 下发结构化研究合同
委派内容至少包含：
- 研究主题
- 必答问题
- 候选来源或来源类型要求
- 最少来源数 / 覆盖要求
- 输出格式
- 禁止项
- 验收标准

### 第 4 步：要求 Claude Code 交付研究包
研究包至少应包含：
- 来源与贡献（标题 + URL + 为什么重要）
- 关键摘录/关键启发
- 初步结论/规则草案
- 断言 -> 来源 映射
- 未决问题 / 冲突点 / 风险

### 第 4.1 步：保留可复用的研究产物
如果这轮调研产出的是稳定机制、可重复流程、可复用结构，而不是一次性结论，
应把成果同时整理成：
- 用户可读的研究包/评估文档
- 后续可复用的知识库条目（Obsidian 风格）
- 必要时补一个简短 reference，记录本次调研中的关键抓手、验证路径与集成判断

相关沉淀见：`references/openhuman-project-research-and-integration.md`

### 第 5 步：Hermes 做二轮复核
复核顺序：
1. 完整性检查
   - 必答项是否都覆盖
   - 来源数量/类型是否达标
   - 是否给出 URL、标题、关键启发
2. 证据检查
   - 每条关键规则是否可回溯到来源
   - 高影响断言是否已抽查原文
3. 冲突处理
   - 若来源有张力，给出裁决逻辑
4. 缺口处理
   - 优先定向返工 Claude Code
   - 不直接自己接管整轮研究
5. 最终综合
   - 只有研究包通过复核后，Hermes 才输出最终稿

### 第 6 步：最终输出保留二阶段痕迹
最终结论至少应回答：
- Claude Code 实际读了哪些来源
- Hermes 复核了哪些关键点
- 哪些结论已通过复核
- 哪些仍存在不确定性
- 若有新增来源，哪些是 review 补充来源

## 当前环境里的重要回退策略

如果 Claude Code 直跑 WebSearch/WebFetch 无法稳定留下“真实检索/真实读取”的可复核证据：

1. Hermes 只做“可达来源筛选”
   - 目的仅是确认哪些 URL 能抓取
   - 不代替 Claude Code 做内容结论
2. 把可达 URL 包交给 Claude Code
3. 明确要求 Claude Code 自己用 terminal 抓取、阅读、归纳
4. 仍按“研究包 -> Hermes 复核”闭环执行

这个回退策略是允许的，因为 Hermes 只做链路排障/来源可达性筛选，不做首轮内容研究。

## 研究交付的结构化模板

对“项目机制 + 集成评估”类调研，优先要求 Claude Code 交付下面五段：

1. 来源与贡献
2. 关键摘录/要点
3. 项目机制与流程图
4. 初步集成评估（按 Hermes / OpenClaw / shared hub / Obsidian / 微信推送分项）
5. 断言 -> 来源 映射 + 未决问题/风险 + 下一步实验

如果文章/产品本身是“知识库、记忆、同步、摘要、路由、压缩、编排”一类系统，复核时必须额外检查：
- 是否能映射到 shared hub 的 curated / inbox / runtime 边界
- 是否能转成 Obsidian 风格 Markdown
- 是否清楚区分本地运行时状态与长期真相源
- 是否存在把外部系统本体误当成内部核心依赖的风险

## 真假委派判定

### 真委派
- Claude Code 负责第一层资料发现与阅读
- Claude Code 交付结构化研究包
- Hermes 负责第二层核验与裁决

### 假委派
- Hermes 已先完成主要研究
- Claude Code 只做补充、润色、背书
- Claude Code 没交来源/摘录/断言映射
- Hermes 最终只是改写 Claude 文案，没有原文抽查

## 委派模板

```text
任务：
请对以下主题做首轮外部调研，不要直接替我写最终用户答复。

研究主题：
<主题>

必须回答：
1. <问题1>
2. <问题2>
3. <问题3>

来源要求：
- 优先阅读这些来源：
  - <URL1>
  - <URL2>
- 至少实际读取 <N> 个外部来源。
- 不要凭记忆总结未读取的内容。

交付格式：
A. 来源与贡献
B. 关键摘录/要点
C. 初步结论/规则草案
D. 断言 -> 来源 映射
E. 未决问题/冲突点/风险

禁止项：
- 不要只给概念性总结
- 不要省略 URL
- 不要把未核实内容写成确定事实
- 不要跳过我要求的输出结构

验收标准：
- 我要基于你的研究包做二阶段复核，所以输出必须可核验、可追踪、可返工。
```

## 复核模板

```text
你提交的是首轮调研包，不是最终稿。现在我要做二阶段复核。

请你按以下方式补齐/澄清：
1. 对每条关键规则，列出对应来源 URL。
2. 标出哪些结论是高确定性，哪些只是推断。
3. 对存在冲突的来源，说明冲突点和你的暂定判断。
4. 对我标记的缺口，补查并返回最小增量结果。

注意：
- 不要重写整份报告；只补齐缺口。
- 继续保持来源可追踪性。
```

## 发送最终稿前检查

- [ ] Claude Code 给出了实际使用的 URL 清单
- [ ] 每个来源有标题/来源名和关键启发
- [ ] 每条关键规则都能回溯到来源
- [ ] 高影响断言已由 Hermes 抽查原文
- [ ] Hermes 在委派前没有完成首轮主要外查
- [ ] Hermes 的新增来源已标注为 review 补充来源
- [ ] 最终稿明确区分来源事实、推导规则、未决问题
- [ ] 若需要 SOP/skill，内容已经写成可执行步骤

## 陷阱

- 先查后派
- 派而不等，自己并行重做同一轮研究
- 只委派结论，不委派证据
- 复核等于复述
- Hermes 发现缺口后自己接管整轮研究
- 把最终 guardrail 错当成中间结果已自动可信
- 只保留一次性报告，不沉淀可复用的流程与结构

## 一句话规则

调研型任务里，Hermes 先当调度与验收者，不当第一研究员；Claude Code 先找证据，Hermes 再裁决证据。
